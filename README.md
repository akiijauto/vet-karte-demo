# vet-karte-demo

動物病院向け 電子カルテ・売上管理システム（**開発途中のプロトタイプ**）の **画面モック**。

👉 **[モックを開く](https://akiijauto.github.io/vet-karte-demo/)**

## これは何か

AIエージェントを用いて単独で開発中のプロトタイプについて、
**画面と設計判断を見ていただくために作った静的なページ**です。

- **動くシステムではありません。** 動くのはページ間のリンクだけで、入力・保存・検索はできません。
- **元のプロトタイプ自体、多くの機能がまだ実装前です。** 入院・DM管理・売上集計・マスタメンテナンス等は作っていません。
- **実システムのソースコードは含みません。**
- 表示しているデータは**すべて架空**で、実在する動物病院・飼い主・動物の情報は一切含みません。
- **外部への通信を行いません。** 読み込むファイルも外部リソースもゼロで、1ファイルで完結します。

## 何を見せているか

主眼は実装ではなく、**「AIの生成物が業務要件を満たすかを、どう検証させるか」という指示設計**です。

受付から会計までの各段階で「何が満たされていれば正しいか」を先に定義し、
AIに自己検証させたうえで人が確認する手順にしました。
金額の算定・計上に関わる箇所は、AIの出力をそのまま採用せず**検算が通ることを採用条件**としています。

ページには、その検証で**実際に検出した不具合を2件**載せています。

1. **全患者のカルテに同じ体温が印字されていた** — 写し漏れた固定値。既存の印刷チェックが用紙からの逸脱しか見ていなかった。
   固定値の不在を全患者 × 画面／印刷の **252ページ**で自動検証する項目を追加して対処
2. **合計額が単価未設定の行を0円として集計していた** — 合計を伏せるのではなく、**未算入の行数を明示する**仕様に是正

どちらも「動くかどうか」を見ているだけでは見つからない種類のものです。

## なぜこの題材か

ドメインは獣医療ですが、論点は「AIに業務システムを作らせる際、品質をどう担保するか」です。
これは経理領域で一貫して取っている**「AIは案を出すまで、確定は必ず人が行う」**という設計思想と同じものです。

## 構成

実物と同じ画面構成で、**ページ間のリンクが実際に動きます**。各ページの内容は固定です。

```
index.html       説明（このモックについて／検出した不具合／設計方針）
menu.html        メニュー画面
 ├ owner.html    飼い主・動物  ──→ karte.html
 └ list.html     外来一覧      ──→ karte.html ──→ accounting.html
style.css        共通スタイル
```

メニューの「入院」「DM管理」「売上集計」「病院設定」「マスタメンテナンス」「CSVエクスポート」は
**実装前**で、押せない状態にしてあります。枠だけ置いてあるのは、全体像のどこを作っているかが
分かるようにするためです。

JavaScript は使っていません（リンクによる遷移のみ）。外部リソースの読み込みも通信もありません。
